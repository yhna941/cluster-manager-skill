# Security model

All mutation CLI commands use managed.engine. It discovers state, compiles a typed operation, validates and saves a plan, previews exact transport/subprocess commands and descriptor-based filesystem actions, obtains local terminal approval, authenticates, executes, verifies and audits. A fresh execution recompiles on the remote host and compares preconditions under a per-host worker lock. Plan digests detect alteration; they are not signatures against the local OS owner. Host fingerprints are bound in addition to normal known_hosts validation. A plan is single-attempt and time-limited.

The root worker has a closed operation schema and a deterministic command compiler. Shell interpolation is not used for request data. Linux directories are traversed with O_NOFOLLOW and mutations use pinned descriptors. Configured roots must actually be mounted, writable, supported filesystems. Existing ACLs and unsafe ancestors are refused. Other root administrators remain outside the worker lock, and changes are not atomic across account databases, filesystems and Samba. The implementation reports partial/unknown outcomes and does not delete newly created data to simulate a rollback.

Samba configuration and service state are never modified. Existing parent shares are inspected. Forced-user shares are rejected when planning new group/private paths. Central identity providers, domain Samba roles, external passdb stores and unix password sync are unsupported for mutation.

Passwords are supplied only through terminal prompts and SSH stdin. Interactive sudo uses a distinct prompt/ready handshake before the JSON worker request. Error messages discard subprocess output to avoid secret disclosure. Audits contain plan IDs, stages and redacted results. Python cannot guarantee in-memory erasure. The local state directory is 0700; plan/audit files are 0600. Audits are durable but not tamper-proof against the local owner/root.

The local OS user, installed source and remote administrator are trusted. A user who can modify the Python source or invoke sudo independently is outside this application boundary. Privileged discovery requires existing sudo authorization too; this tool neither grants it nor edits sudoers. The user must independently verify first-use host keys.
