# Security reporting

Do not post passwords, private keys, passdb files or sensitive host inventories in public issues. Report suspected approval bypasses, command/path injection, unexpected configuration writes or secret leaks privately to the repository owner through GitHub's available private reporting/contact mechanisms. Include a minimal simulated reproducer and affected commit without production secrets.

See docs/security-model.md for the trust boundary and unsupported operations. No claim of a third-party security audit is made. Privileged use should first be tested in a disposable environment with the site's actual policy.
